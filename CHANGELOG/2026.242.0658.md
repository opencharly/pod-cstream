# 2026.242.0658 — fix: advance the pod-hyprland pin so the corpus resolves ONE version

## Summary

Advance the pinned `pod-hyprland` from `v2026.241.1545` to `v2026.242.0634`, so the corpus
resolves **one** version of it.

`layer-cstream-desktop` composes this candy *and* `pod-hyprland` directly. When the metalayer
advanced to the new tag and this candy did not, composing them produced:

```
Warning: candy github.com/opencharly/pod-hyprland resolved to multiple versions;
         using newest 2026.242.0620 (from …@v2026.242.0634), ignoring 2026.241.1140 (from …@v2026.241.1545)
Warning: candy github.com/opencharly/plugin-wl/candy/plugin-wl resolved to multiple versions;
         using newest 2026.242.0600 (from …@v2026.242.0610), ignoring 2026.187.1200 (from …@v2026.240.1326)
```

Taking the newest happens to be the right answer here, but it is a resolution **charly** made
rather than one the candy declared — and the second line shows it cascading a level deeper into
`plugin-wl`, which is where the Hyprland dispatcher fix lives. A composition that depends on
charly's tie-break is one edit away from resolving the *other* way.
