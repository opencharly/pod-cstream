# 2026.242.1603 — feat(WP4): gate the resize at the COMPOSITOR, not just the streamer

## Summary

Advances the pinned streamer revision to `b0756118` — `charly-streamer#8`, merged, which adds the
runtime control socket — and authors **WP4's gate** against it.

**The gate observes the compositor, not just the streamer.** Each resize is paired with a
`wl: hypr-monitors` observation, because the socket reply proves only that the *streamer* applied
new caps and says nothing about whether the compositor reconfigured its output. The plan records the
concrete hazard: Aquamarine snaps an unsatisfiable configure to 1280×720 **in silence**. So neither
"no error" nor "the streamer said OK" is evidence here.

Measured on the live bed, the full chain:

```
resize 1600 900  ->  socket: OK resize 1600x896  ->  monitor: "width": 1600  "height": 896
resize 640 480   ->  socket: OK resize 640x480   ->  monitor: "width": 640   "height": 480
```

A capsfilter rewrite propagates through gst-wayland-display to Hyprland's monitor, and the
compositor reports **896** — the rounded height.

## ⚠️ The plan's WP4 gate names a size that cannot apply

The plan says *"1600×900, 3840×2160 and 640×480, each asserting `wl: hypr-monitors` reports the
requested size."*

`Geometry::sanitised()` rounds to a multiple of 8, and **900 is not one**: it applies as **896**. A
gate asserting the *requested* 900 would fail against entirely correct behaviour. This gate asserts
`1600x896`, with the reason written inline in the bed so the next reader does not "correct" it back.

`640×480` is asserted as-is (both multiples of 8). `3840×2160` is deliberately **not** included —
see *What this does not do*.

## Why both dimensions, with their JSON keys

The first version of this gate asserted `contains: "1600"`. That passes — and it would pass just as
happily against a coordinate or a refresh rate. **`896` is the value that can only appear if the
round-to-8 reached the compositor**, so both dimensions are now asserted keyed:

```yaml
- contains: "\"width\": 1600"
- contains: "\"height\": 896"
```

A check that cannot fail is worse than no check, because it reports safety. This one fails if the
compositor ignores the resize, if it snaps to another size, or if the rounding stops at the
capsfilter.

## What this does NOT do

**`3840×2160` is not gated here.** The plan lists it, but this bed runs in a rootless container on
a shared iGPU, and a 4K reconfigure is a materially different resource claim from the two sizes
above — I have not measured whether it succeeds, and a gate I have not run is not a gate. It belongs
with `check-cstream-vm` (WP9b), where the GPU surface is declared rather than borrowed. Recorded
here rather than silently dropped.

The rate limit is handled by a bounded retry on the `rate-limited` reply **specifically**, failing
fast on any other error, so step-timing changes cannot turn this into a flake and a genuine failure
still fails immediately.
