# 2026.242.1124 — feat: the streamer IS the Wayland parent

## Summary

`cstream-parent` now execs **`cstream-streamer`**. The service name is deliberately kept — every
check and consumer that waits on `cstream-parent` keeps working — but what runs is the streamer,
with `CSTREAM_FRAME_DIR` enabling the tap the frame-content gate reads. One pipeline now provides
what two used to.

**Why the separate parent could not stay.** `waylanddisplaysrc` creates a compositor **and holds
the render node**, so a second one cannot observe the first's display. A streamer running beside a
parent captured its **own empty compositor** while the desktop drew into the other — which is
exactly why signalling negotiated a WebRTC session end-to-end and no media ever followed. The same
conclusion arrived three ways: that, a pod that **died mid-run** with two long-lived GWD displays
(19 checks lost to `no container with name`), and two streamers colliding on the fixed signalling
port.

This is the architecture's own statement — *"the streamer **is** the Wayland parent"* — finally
implemented rather than approximated.

## Change classification

**Change class:** candy/box-config — **four things, and nothing else**:

| item | change |
|---|---|
| `cstream-parent` service `exec` | `/usr/local/bin/cstream-parent` → `/usr/local/bin/cstream-streamer` |
| its `env` | adds `CSTREAM_ENCODE`, `CSTREAM_RENDER_NODE`, `CSTREAM_FRAME_DIR` |
| pinned `charly-streamer` commit | `3898e9a` → `113795b` (the merged `#7`, which carries the parent role) |
| candy `version:` | bumped |

**The build step is NOT touched.** An earlier revision of this branch duplicated the streamer's
build/install pair, which was already present on `main` — a copy-paste error, correctly blocked,
and removed. No Go, no schema, no workflow.

**Verification gate:** `check-cstream-pod` — and specifically the checks that fail without it.

**Breaking change + rollback:** the service runs a different binary under the same name. Rollback
returns to a split parent/streamer where nothing can consume the stream.

**Producer → consumer order:** satisfied — `113795b` is `charly-streamer`'s `main` **after `#7`
merged**, so this pins a merged ref rather than a feature-branch SHA. It carries the parent role,
the frame tap, the runtime-dir creation and the bus-error reporting.

## What this does NOT claim

A consumer receiving decodable video. Signalling is proven end to end — producer registers,
consumer registers as `[Consumer]`, `startSession` sent, session started — then no media, with no
ICE/DTLS error. That is **no longer** the empty-compositor problem: the tap proves this parent has
real content. Tracked as WP3d. Until it is understood, `cstream-frame-probe` is deliberately **not
staged** and `cstream: frame` is **not offered** — shipping a probe with no gate is what got
`pod-cstream#5` blocked, correctly.
